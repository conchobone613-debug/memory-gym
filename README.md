# 기억력 훈련소 (memory-gym)

기억력 스포츠 개인 훈련용 PWA. 서버 없이 브라우저 안에서만 돈다.

```bash
npm install
npm run dev     # http://localhost:5173
npm run build   # dist/ 로 정적 빌드 (PWA 포함)
```

스택: Vite 8 · React 19 · TypeScript · Dexie(IndexedDB) · Tailwind 4 · vite-plugin-pwa

## 핵심 설계

**모든 것은 `(세트, 키 문자열)` 한 쌍으로 식별한다.** 키가 문자열(`'00'`, `'SJ'`, `'S7-HK'`)이라
000–999 확장도 2-카드 1352 확장도 스키마 변경 없이 세트만 추가하면 된다.

**카드는 이미지를 따로 만들지 않는다.** 무늬→숫자 변환으로 A~10 카드 40장은 숫자 세트의
이미지를 재사용하고, 별도로 저장하는 것은 J/Q/K 인물 12장뿐이다. 덕분에 카드 훈련의 오답이
숫자 드릴 통계·히트맵에 그대로 합산된다.

## 구조

```
src/

  lib/

    cards.ts      카드 ↔ 이미지 키 변환, 회상 입력 정규화
    random.ts     crypto.getRandomValues + Fisher-Yates (모듈로 편향 제거)

    navlock.ts    훈련 중 전역 단축키 잠금
  pages/          화면 7개
  components/ui.tsx
```

## 드릴 3단계

자음 매핑이 몸에 붙기 전에 이미지 드릴부터 하면 두 가지를 한꺼번에 더듬게 되어 늘지 않는다.
그래서 앞에 두 단계를 둔다.

| 단계 | 하는 일 | 답하는 법 |
| --- | --- | --- |
| 1 | 숫자 하나 ↔ 자음 하나 (`7` ↔ `ㅅㅆ`) | 자판의 자음 키 또는 숫자 키를 그냥 누른다 |
| 2 | 두 자리 ↔ 자음 두 개 (`47` ↔ `ㄹ · ㅅㅆ`) | 위와 같음, 두 번 |
| 3 | 자극 → 이미지 (본 훈련) | `Space` → `D` 맞음 / `F` 틀림 |

**보기에서 고르게 하지 않는다.** 한글 자판은 자음이 물리 키에 그대로 있어 바로 칠 수 있고,
고르는 것(재인)보다 떠올려 치는 것(회상)이 훨씬 강하게 붙는다. `lib/keyjamo.ts` 가
`event.code`(물리 위치) → 자음으로 바꾸므로 한/영 상태와 무관하게 동작한다. 쌍자음은 같은
숫자에 속하므로 기본 자음만 받는다 — 1 은 `ㄱ` 이든 `ㅋ` 이든 맞다.

방향은 셋 중에 고른다. 기본은 **숫자 → 자음**이다. 숫자를 외우는 것이 목적이고, 암기 중에
시간에 쫓기는 쪽이 이 방향이기 때문이다. `자음 → 숫자` 는 회상에서 막혔을 때 되짚는 길이라
양쪽이 어느 정도 붙은 뒤에 섞는다. 고른 방향은 설정에 저장된다.

1·2단계 기록은 `mappingAttempts`(원시) 와 `mappingStats`(파생) 에 따로 쌓이며,
대시보드의 '자음 매핑 숙련도' 에서 어느 숫자가 아직 안 붙었는지 볼 수 있다.
정확도 95% 이상 · 중앙 반응시간 2초 이하가 되면 다음 단계로 넘어가라고 알려 준다.

## 추천 기본 이미지

`이미지 세트 → 추천 이미지 불러오기` 버튼이 숫자 100개와 인물 카드 12장을 한 번에 채운다
(`src/data/starter.ts`). **비어 있는 칸에만 들어가고 이미 채운 칸은 절대 덮지 않는다.**

목록을 만든 원칙:

1. 모든 이름의 초성이 키 코드로 시작한다 — 3음절 이상이면 앞 두 초성만 맞으면 된다
2. 추상명사를 쓰지 않는다. 눈에 보이고 만져지는 것만
3. 같은 십의 자리 안에서 범주를 흩는다
4. 헷갈릴 짝을 떼어 놓는다 (사자와 호랑이를 같이 넣지 않는 식)
5. 세부 묘사에 색·크기·동작 같은 감각 단서를 하나씩 넣는다

인물 카드는 무늬마다 세계를 하나씩 준다 — ♠ 싸우는 사람 / ♥ 불과 사랑 / ♦ 캐고 가진 사람 /
♣ 풀과 나무. 여기는 초성 규칙이 없으므로 실제로 아는 사람으로 바꿀수록 강해진다.

안 맞는 칸은 대시보드 히트맵에서 느리거나 붉게 나온다. 그때 바꾸면 된다.

## 데이터

전부 브라우저 IndexedDB 안에만 있다. 서버로 나가지 않는다. 기기를 옮길 때는
설정 → 전체 백업 내려받기로 JSON 파일을 받아 새 기기에서 복원한다.

모든 드릴 시도와 실전 칸은 원시 데이터로 남는다 (`drillAttempts`, `recallCells`).
`imageStats` 는 조회 속도를 위한 파생 캐시이며 원본이 아니다.

## 카드 입력 표기

회상 칸에는 `s7` · `ha`(에이스) · `dt` 또는 `d10` · `ck` 형태로 적는다.
`1` 단독은 A 와 10 이 모호해 받지 않는다.

## SRS 우선순위

```
priority = 0.45 * 반응시간 백분위
         + 0.40 * 오답률
         + 0.15 * 마지막으로 본 뒤 경과 (3일 기준)
         + 0.5  (반응시간 상위 20% = 가장 느린 쪽)
         + 0.8  (직전 오답)
         = 1.5  (아직 한 번도 안 본 이미지)
```

출제 목록은 우선순위 상위 70% + 무작위 30%. 약점만 돌리면 잘 되던 이미지가 조용히 녹슨다.
