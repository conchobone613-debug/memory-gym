# 기억력 훈련소 (memory-gym)

기억력 스포츠 개인 훈련용 PWA. 서버 없이 브라우저 안에서만 돈다.

**https://conchobone613-debug.github.io/memory-gym/**

```bash
npm install
npm run dev     # http://localhost:5173/memory-gym/  (base 가 /memory-gym/ 이다)
npm run build   # dist/ 로 정적 빌드 (PWA 포함)
```

master 에 밀면 GitHub Actions 가 빌드해 Pages 로 올린다 (`.github/workflows/pages.yml`).
해시 라우팅이라 서버 재작성 규칙이 없어도 깊은 경로가 그대로 열린다.

스택: Vite 8 · React 19 · TypeScript · Dexie(IndexedDB) · Tailwind 4 · vite-plugin-pwa

## 핵심 설계

**모든 것은 `(세트, 키 문자열)` 한 쌍으로 식별한다.** 키가 문자열(`'00'`, `'SJ'`, `'S7-HK'`)이라
000–999 확장도 2-카드 1352 확장도 스키마 변경 없이 세트만 추가하면 된다.

**카드는 이미지를 따로 만들지 않는다.** 무늬→숫자 변환으로 A~10 카드 40장은 숫자 세트의
이미지를 재사용하고, 별도로 저장하는 것은 J/Q/K 인물 12장뿐이다. 덕분에 카드 훈련의 오답이
숫자 드릴 통계·히트맵에 그대로 합산된다.

## 화면

| 경로 | 화면 |
| --- | --- |
| `/` | 홈 — 오늘·이번 주 요약, 세 층으로 들어가는 문 |
| `/assets` | **자산** — 내가 만들어 두는 것 |
| `/assets/sets` · `/assets/sets/:id` | 이미지 세트 목록 · 10×10 편집기 |
| `/assets/palaces` | 궁전·장소 CRUD, 워크스루 |
| `/basics` | **기초** — 1단계 자음 / 2단계 두 자리 / 3단계 이미지 |
| `/events` · `/events/:id` | **종목** — 표준 10종목 목록 · 종목 상세(연습·실전·내 기록) |
| `/practice` | 실행기. 종목에서 `?preset=…&event=…&run=easy\|real` 로 들어온다 |
| `/stats` | 대시보드 |
| `/settings` | 설정 |

## 왜 세 층인가

**자산**은 만드는 것, **기초**는 자산을 몸에 붙이는 것, **종목**은 그걸로 겨루는 것이다.

변환 드릴을 종목 아래에 두지 않은 이유가 있다. 자음 매핑과 이미지 변환은 숫자·카드·이진수·
날짜 종목 전부의 **공통 기반**이라 어느 한 종목에 속하지 않는다. 스피드 숫자 안에 넣으면
카드 종목에 같은 드릴이 또 있어야 하고, 1단계(자음 하나)를 하려면 어느 종목으로 들어가야
하는지 답이 없어진다.

## 종목 안의 연습과 실전

| | 연습 | 실전 |
| --- | --- | --- |
| 시간 | 재지 않음 | 대회 규격 |
| 분량 | 종목 기본의 1/4 | 그대로 |
| 채점 | 이미지 이름 + 궁전 장소 표시 | 숫자만 |

**연습의 값어치는 '느리게 하기'가 아니라 '보조를 켜는 것'이다.** 시간만 없애면 그냥 느린
실전이다. 궁전을 고르면 회상 칸과 채점 칸에 장소 이름이 붙어, 궁전과 이미지가 한 화면에서 만난다.

## 키보드

| 곳 | 키 |
| --- | --- |
| 드릴 3단계 | `Space` 떠올림 · `D` 맞음 · `F` 틀림 · `Esc` 중단 |
| 드릴 1·2단계 | 자음 답은 자판의 자음 키, 숫자 답은 숫자 키 (한/영 무관) |
| 세트 편집 | 방향키 이동 · `Enter` 저장·다음 · `Shift`+`Enter` 다음 빈칸 |
| 실전 | 암기 `Enter` 조기 종료 · 회상 `Ctrl`+`Enter` 제출 · 칸은 자동 진행 |
| 채점 | `1`~`4` 원인 태그 · `↑` `↓` 칸 이동 |
| 워크스루 | `Space` 가리기 · `→` 다음 · `←` 이전 |

## 구조

```

  lib/

    cards.ts      카드 ↔ 이미지 키 변환, 회상 입력 정규화
    random.ts     crypto.getRandomValues + Fisher-Yates (모듈로 편향 제거)
    srs.ts        우선순위 계산 + 출제 목록 생성

    navlock.ts    훈련 중 전역 단축키 잠금
  pages/          화면 7개
  components/ui.tsx
```

## 대회 종목

`data/events.ts` 가 표준 10종목의 이름·시간·설명과 **열림/잠김**을 들고 있다.
열린 종목은 `/practice?preset=…` 으로 실전 모드를 알맞은 프리셋으로 열어 준다.
잠긴 종목에는 **무엇이 있어야 열리는지**를 적는다 — 단어 목록, 얼굴 사진, 여러 벌 지원처럼
대부분 자료나 기능 한 조각이 없어서 막힌 것이라, 그걸 적어 두면 다음에 무엇부터 할지 정해진다.

시간 값은 WMSC·IAM 기준이며 연맹과 해에 따라 다르다. 훈련 목표를 잡는 기준으로만 쓴다.

**대회와 다른 점**: 대회는 '정해진 시간 안에 최대한 많이' 인데 이 앱의 실전 모드는
'길이를 정해 놓고 시간을 잰다'. 방향이 반대다. 열린 종목도 이 점에서는 대회와 같지 않다.

## 자음 매핑은 왜 이렇게 정해졌나

임의로 붙인 것이 아니라 **가나다 순서 그대로**다. 대표 자음만 세면
`ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅈ ㅎ` 아홉 개가 1~9 이고, 동그라미를 닮은 `ㅇ` 만 0 으로 빠진다.
그래서 `ㅈ` 이 여덟 번째라 8, `ㅎ` 이 마지막이라 9 다.

거센소리·된소리는 입에서 같은 자리에서 나는 소리라 짝이 되는 대표 자음에 얹는다 —
`ㅋㄲ→1` `ㅌㄸ→3` `ㅍㅃ→6` `ㅆ→7` `ㅊㅉ→8`. 덕분에 열아홉 자음이 정확히 열 칸에 들어간다.

`components/ChosungKey.tsx` 가 이 표를 설정 화면과 초급 드릴에 띄운다. 현재 설정값을 그대로
읽으므로 회장이 매핑을 바꾸면 표도 따라 바뀐다.

## 드릴 3단계

자음 매핑이 몸에 붙기 전에 이미지 드릴부터 하면 두 가지를 한꺼번에 더듬게 되어 늘지 않는다.
그래서 앞에 두 단계를 둔다.

| 단계 | 하는 일 | 답하는 법 |
| --- | --- | --- |
| 1 | 숫자 하나 ↔ 자음 하나 (`7` ↔ `ㅅㅆ`) | 자판의 자음 키 또는 숫자 키를 그냥 누른다 |
| 2 | 두 자리 ↔ 자음 두 개 (`47` ↔ `ㄹ · ㅅㅆ`) | 위와 같음, 두 번 |
| 3 | 자극 → 이미지 (본 훈련) | `Space` → `D` 맞음 / `F` 틀림 |

**보기에서 고르게 하지 않는다.** 한글 자판은 자음이 물리 키에 그대로 있어 바로 칠 수 있고,
고르는 것(재인)보다 떠올려 치는 것(회상)이 훨씬 강하게 붙는다. `lib/keyjamo.ts` 가
`event.code`(물리 위치) → 자음으로 바꾸므로 한/영 상태와 무관하게 동작한다. 쌍자음은 같은
숫자에 속하므로 기본 자음만 받는다 — 1 은 `ㄱ` 이든 `ㅋ` 이든 맞다.

방향은 셋 중에 고른다. 기본은 **숫자 → 자음**이다. 숫자를 외우는 것이 목적이고, 암기 중에
시간에 쫓기는 쪽이 이 방향이기 때문이다. `자음 → 숫자` 는 회상에서 막혔을 때 되짚는 길이라
양쪽이 어느 정도 붙은 뒤에 섞는다. 고른 방향은 설정에 저장된다.

1·2단계 기록은 `mappingAttempts`(원시) 와 `mappingStats`(파생) 에 따로 쌓이며,
대시보드의 '자음 매핑 숙련도' 에서 어느 숫자가 아직 안 붙었는지 볼 수 있다.

## 단계별 목표

`db/goals.ts` 가 세 단계의 통과 기준을 한 곳에서 정한다.

| 단계 | 반복 | 정확도 | 중앙 반응시간 | 통과하면 |
| --- | ---: | ---: | ---: | --- |
| 1 | 모든 칸 3회 | 95% | 1.5초 | 2단계 |
| 2 | 모든 칸 3회 | 95% | 3초 | 3단계 |
| 3 | 채운 이미지 전부 3회 | 95% | 3초 | 실전 |

반응시간 기준이 단계마다 다른 이유는 하는 일이 다르기 때문이다 — 2단계는 조회를 두 번 하므로
1단계의 두 배로 잡는다.

**통과 여부만 알리지 않고 세 조건을 각각 보여 준다.** '언제 끝나나' 에 답이 되어야 하기
때문이다. 드릴 설정 화면, 세션을 마친 결과 화면, 대시보드 세 곳에 같은 패널이 뜬다.

## 시간 기록

드릴 진행 중에는 머리말에 경과 시간이 돌고, 결과 화면에 **총 걸린 시간**과 **문항당 평균**이
남는다. 반응시간(문제를 보고 답할 때까지)과 총 시간(훈련에 실제로 쓴 시간)은 다른 값이며
둘 다 필요하다. 실전 모드는 암기 사용 · 회상 사용 · 합계를 따로 보여 준다.

## 추천 기본 이미지

`이미지 세트 → 추천 이미지 불러오기` 버튼이 숫자 100개와 인물 카드 12장을 한 번에 채운다
(`src/data/starter.ts`). **비어 있는 칸에만 들어가고 이미 채운 칸은 절대 덮지 않는다.**

목록을 만든 원칙:

1. 모든 이름의 초성이 키 코드로 시작한다 — 3음절 이상이면 앞 두 초성만 맞으면 된다
2. 추상명사를 쓰지 않는다. 눈에 보이고 만져지는 것만
3. 같은 십의 자리 안에서 범주를 흩는다
4. 헷갈릴 짝을 떼어 놓는다 (사자와 호랑이를 같이 넣지 않는 식)
5. 세부 묘사에 색·크기·동작 같은 감각 단서를 하나씩 넣는다

인물 카드는 무늬마다 세계를 하나씩 준다 — ♠ 싸우는 사람 / ♥ 불과 사랑 / ♦ 캐고 가진 사람 /
♣ 풀과 나무. 여기는 초성 규칙이 없으므로 실제로 아는 사람으로 바꿀수록 강해진다.

안 맞는 칸은 대시보드 히트맵에서 느리거나 붉게 나온다. 그때 바꾸면 된다.

## 데이터

전부 브라우저 IndexedDB 안에만 있다. 서버로 나가지 않는다. 기기를 옮길 때는
설정 → 전체 백업 내려받기로 JSON 파일을 받아 새 기기에서 복원한다.

모든 드릴 시도와 실전 칸은 원시 데이터로 남는다 (`drillAttempts`, `recallCells`).
`imageStats` 는 조회 속도를 위한 파생 캐시이며 원본이 아니다.

## 카드 입력 표기

회상 칸에는 `s7` · `ha`(에이스) · `dt` 또는 `d10` · `ck` 형태로 적는다.
`1` 단독은 A 와 10 이 모호해 받지 않는다.

## SRS 우선순위

```
priority = 0.45 * 반응시간 백분위
         + 0.40 * 오답률
         + 0.15 * 마지막으로 본 뒤 경과 (3일 기준)
         + 0.5  (반응시간 상위 20% = 가장 느린 쪽)
         + 0.8  (직전 오답)
         = 1.5  (아직 한 번도 안 본 이미지)
```

출제 목록은 우선순위 상위 70% + 무작위 30%. 약점만 돌리면 잘 되던 이미지가 조용히 녹슨다.

## 같은 문제가 연달아 나오지 않게

문항 수가 칸 수보다 많으면 같은 칸이 여러 번 나올 수밖에 없다 (1단계는 10칸인데 20문항).
그때 단순히 섞기만 하면 바로 앞 문제와 같은 것이 붙어 나오고, 그러면 기억을 꺼내는 게 아니라
방금 본 답을 되뇌게 되어 훈련이 되지 않는다.

`random.ts` 의 `spread()` 가 남은 개수가 가장 많은 것부터 집되 직전 것은 건너뛴다.
어떤 항목이 전체의 절반을 넘지 않는 한 붙는 일이 없다. 초급 큐와 이미지 큐 양쪽에서 쓴다.
